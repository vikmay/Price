# Cache Clearing via `/reload` — What It Does

## Summary

Команда `/reload` (тільки для admin) очищає **in-memory TTL кеш результатів пошуку** (`SimpleTTLCache`). Вона **не перезавантажує** базу даних, не імпортує товари повторно і не перезапускає бота.

## Де знаходиться

**Файл**: `app/handlers.py`  
**Визначення**: обробник `_reload` в середині `register_handlers()`

```python
@router.message(Command("reload"))
async def _reload(message: Message) -> None:
    if not await _require_admin(message):
        return
    cache.clear()
    await _answer(message, "Ок. Кеш очищено.")
```

## Який саме кеш?

`cache` — це екземпляр `SimpleTTLCache`, створений на початку `register_handlers()`:

```python
cache = SimpleTTLCache(ttl_seconds=30, max_items=300)
```

Клас визначений у тому ж файлі (`app/handlers.py`; `class SimpleTTLCache`):

- **Зберігання**: in-memory dict (`self._items: dict[str, CacheEntry]`)
- **Ключі**: формат `"admin:<запит>"` або `"user:<запит>"` (див. `_cache_key()`)
- **Значення**: попередньо відформатовані HTML рядки результатів пошуку (рядки товарів)
- **TTL**: 30 секунд на запис (прострочені записи пропускаються і ліниво видаляються)
- **Max items**: 300 (LRU-подібне витіснення при переповненні — спочатку видаляє прострочені, інакше видаляє один будь-який)

## Що дає очищення

`cache.clear()` викликає `self._items.clear()` — **видаляє всі кешовані відповіді пошуку безумовно**.

Після `/reload`:

- Наступний пошуковий запит від будь-якого користувача (admin або allowed) **звернеться до SQLite бази свіжим запитом** замість повернення кешованого рядка.
- Не впливає на базу даних, сесії користувачів або стан бота.

## Коли адміну варто використовувати `/reload`?

- Після **ручного оновлення бази товарів** поза ботом (наприклад, прямі SQLite редагування, або окремий запуск `scripts/import_html.py`).
- Якщо старі результати пошуку викликають підозру (застарілі) і адмін не хоче чекати 30 секунд до закінчення TTL.
- **Примітка**: Коли товари імпортуються через обробник **Завантаження HTML документа** (`F.document`), кеш **автоматично очищається** після завершення імпорту (як при успіху, так і при помилці). Тому `/reload` потрібен лише для змін бази даних, зроблених поза ботом.

## Візуальна схема

```
User sends /reload → _require_admin перевіряє роль → cache.clear() → "Ок. Кеш очищено."
```

Жодних записів у БД, жодних реімпортів, жодних перезапусків.

## Внутрішній клас: `SimpleTTLCache`

| Метод             | Поведінка                                                                                                                  |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `get(key)`        | Повертає кешований текст, якщо не прострочений; інакше видаляє запис і повертає `None`                                     |
| `set(key, value)` | Зберігає з `expires_at = now + ttl_seconds`. Витісняє, якщо перевищено `max_items` (спочатку видаляє прострочені, інакше один будь-який запис) |
| `clear()`         | Видаляє ВСІ записи безумовно                                                                                               |

## Відновлення після помилок

Якщо `/reload` викине виняток (дуже малоймовірно), адмін отримає "Доступ заборонено" для не-admin, або виняток спливе до обробників помилок aiogram диспетчера. Спеціального відновлення не потрібно, оскільки кеш існує тільки в пам'яті.

---

**Висновок**: `/reload` — це легкова операція, яка просто скидає in-memory кеш результатів пошуку, щоб наступні запити читали свіжі дані з SQLite. Жодних важких операцій (DROP TABLE, реімпорт, перезапуск) вона не виконує.
