# Кеш у боті — пояснення

## Що це за кеш?

Це **in-memory TTL-кеш** (клас `SimpleTTLCache`), визначений у файлі `app/handlers.py`. Він зберігає попередньо відформатовані HTML-рядки результатів пошуку товарів, щоб **не робити повторний запит до SQLite бази даних** для того самого пошукового тексту протягом короткого проміжку часу.

## Де зберігається?

Кеш зберігається **в оперативній пам'яті (RAM)** Python-процесу. Ніяких файлів на диску, ніяких зовнішніх сховищ (Redis, Memcached тощо).

Конкретно:

- Об'єкт `cache = SimpleTTLCache(ttl_seconds=30, max_items=300)` створюється всередині функції `register_handlers()` в `app/handlers.py`.
- Дані зберігаються в полі `self._items: dict[str, CacheEntry]` — звичайний Python-словник.
- Кожен запис — це `CacheEntry(text=str, expires_at=float)` — дата-клас із текстом відповіді та часом закінчення TTL.

## Що саме зберігається?

Ключ: рядок формату `"admin:<текст_запиту>"` або `"user:<текст_запиту>"` (див. функцію `_cache_key()`).

Значення: **готова HTML-відповідь** — це рядок, складений із рядків товарів, відформатованих функціями:

- `_format_match_line(code, name, price)` — для звичайного користувача (без закупівельної ціни)
- `_format_match_line_admin(code, name, price, purchase_price)` — для адміна (із закупівельною ціною в дужках)

Наприклад, кешоване значення може виглядати так:

```
12345 Товар А — <b>150.00</b>
67890 Товар Б — <b>200.50</b> (<b>120.00</b>)
```

## Чим допомагає?

1. **Зменшує навантаження на SQLite** — повторні запити того самого тексту не ходять у БД, а беруться з пам'яті.
2. **Пришвидшує відповідь користувачу** — відформатований HTML уже готовий, не треба знову виконувати SQL-запит, ітерувати результати й форматувати.
3. **Зменшує затримки** при масових однотипних запитах (наприклад, кілька адмінів перевіряють однаковий код товару).

## Життєвий цикл

- TTL кожного запису — **30 секунд**.
- Максимум — **300 записів**. При перевищенні спочатку видаляються протерміновані записи (половина), якщо їх нема — один найстаріший.
- Кеш автоматично **очищається** при:
    - імпорті товарів через завантаження HTML-файлу (як на успіху, так і на помилці)
    - команді `/reload` (адмін)
- Кеш **не очищається** при позапланових змінах БД (наприклад, прямому редагуванні SQLite).

## Ручне очищення

Адміністратор може виконати `/reload`, що викличе `cache.clear()` — повне очищення всіх записів. Після цього наступний пошук піде в SQLite.
